# Сенс · Ukrainian WSD audit

Локальний інструмент авторської ручної валідації [українського WSD бенчмарку](https://huggingface.co/datasets/yuriilaba/ukrainian_wsd_benchmark). Український інтерфейс, сліпе початкове судження, збереження прогресу та відтворюваний дослідницький звіт.

## Встановлення

### 1. Підготуйте середовище

Установіть **Node.js версії 22.18 або новішої** та **npm**. Якщо вони вже встановлені й версія Node.js відповідає цій вимозі, цей крок можна пропустити.

**На macOS:**

1. Відкрийте [офіційну сторінку завантаження Node.js](https://nodejs.org/en/download).
2. Виберіть версію з позначкою **LTS**, не нижчу за **22.18**, та операційну систему **macOS**.
3. Завантажте **macOS Installer (`.pkg`)**.
4. Відкрийте завантажений `.pkg` файл і пройдіть кроки встановлення: **Continue → Agree → Install**. Якщо macOS попросить підтвердження, введіть пароль свого облікового запису на Mac. Інсталятор установлює **Node.js і npm разом**; окремо завантажувати npm не потрібно. Цей спосіб також дозволяє встановити новішу версію Node.js, якщо поточна застаріла. [Документація npm про встановлення](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm/).
5. Після завершення закрийте попередні вікна термінала. Натисніть **⌘ + Space**, введіть **Terminal** і натисніть **Enter**, щоб відкрити нове вікно.
6. Перевірте встановлення:

```sh
node --version
npm --version
```

Перша команда має показати версію Node.js **`v22.18.0` або новішу**, друга — номер версії npm. Якщо бачите `command not found`, перевірте, що інсталятор завершив роботу, і відкрийте нове вікно Terminal. Після успішної перевірки перейдіть до кроку 2 нижче.

Для встановлення залежностей потрібен інтернет. Окремо встановлювати SQLite, налаштовувати сервер бази даних, створювати обліковий запис Cloudflare або додавати API ключі не потрібно. Python потрібен лише для необов’язкової незалежної перевірки статистики.

### 2. Відкрийте папку проєкту

Клонуйте репозиторій і перейдіть у його кореневу папку — ту, де розташовані `package.json` і `package-lock.json`:

```sh
git clone https://github.com/YuriiLaba/ukrainian-wsd-benchmark-labeling-tool.git
cd ukrainian-wsd-benchmark-labeling-tool
```

Якщо ви вже скопіювали або розпакували проєкт, відкрийте його наявну папку без повторного клонування. Підставте її фактичний шлях, якщо вона має іншу назву. Усі подальші команди виконуйте з папки, де розташований `package.json`.

### 3. Установіть залежності

```sh
npm ci
```

Команда встановлює версії пакетів, зафіксовані у `package-lock.json`. Дочекайтеся успішного завершення. Цей крок потрібен після першого копіювання проєкту або оновлення залежностей; перед кожним запуском повторювати його не потрібно.

### 4. Запустіть застосунок

```sh
npm run dev -- --hostname 127.0.0.1
```

Відкрийте адресу, надруковану в терміналі, зазвичай **http://127.0.0.1:5173**. Залишайте термінал із сервером відкритим під час роботи. Для звичайного локального запуску попередня збірка не потрібна.

Щоб зупинити сервер, натисніть `Ctrl+C` у його терміналі. Щоб повернутися до роботи, знову виконайте команду запуску з папки проєкту — збережені оцінки залишаться в базі.

### Альтернатива: запуск зібраної версії

```sh
npm run build
npm start
```

Відкрийте адресу, яку надрукує Wrangler: вона може відрізнятися від порту сервера розробки. Обидві команди працюють локально й не публікують застосунок. Після зміни вихідного коду перед `npm start` повторіть `npm run build`.

## Перший запуск і завантаження бенчмарку

1. Натисніть **«Завантажити з Hugging Face»**. За замовчуванням використовується commit `0e361daf8cfb233e8b5b4cb365d966e4460886a2`, а не рухома гілка `main`.
2. Якщо мережа недоступна, відкрийте **«Версія та локальний імпорт»** і виберіть заздалегідь завантажений JSONL. Якщо у вашій копії проєкту є `data/huggingface_supported_grac_metadata.jsonl`, можна вибрати цей файл. Каталог `data/` ігнорується Git, тому у свіжій копії він може бути відсутній.
3. Вкажіть ім’я перевіряльника й створіть проєкт. Типові параметри: **400 прикладів**, seed **42**. Менші вибірки можна використовувати для ознайомлення; дослідницька перевірка має бути окремим проєктом.
4. Спочатку оберіть значення, «Жодне значення не підходить» або невизначеність. Натисніть **«Зафіксувати й відкрити мітку»**.
5. Порівняйте судження з автоматичною міткою та явно збережіть підсумкову оцінку. Невизначені випадки потребують причини. Пропуск залишає приклад у вибірці.
6. Після завершення всієї вибірки відкрийте **«Результати»**: там доступні частки, 95% довірчий інтервал і текст для дослідження.

Після встановлення залежностей інтернет потрібен лише для завантаження бенчмарку. Після імпорту всі операції перевірки виконуються локально. Додатковий контекст із GRAC автоматично не отримується.

### Клавіші

- `1–9`: вибір значення; після відкриття мітки `1–3` задають підсумковий результат.
- `Ctrl+Enter` / `⌘+Enter`: зафіксувати початковий вибір або зберегти оцінку й перейти далі.
- `Alt+←` / `Alt+→`: попередній / наступний приклад.

## Якщо встановлення або запуск не вдається

| Проблема | Що зробити |
|---|---|
| `node` або `npm` не знайдено | Установіть Node.js разом із npm, відкрийте новий термінал і повторіть перевірку версій. |
| Помилка `EBADENGINE` або непідтримувана версія Node.js | Оновіть Node.js до версії ≥22.18, потім повторіть `npm ci`. |
| `ENOENT` для `package.json` | Перейдіть у кореневу папку проєкту перед виконанням команд. |
| `ENOTFOUND`, `EAI_AGAIN` або помилка завантаження пакетів | Перевірте інтернет і налаштування проксі, потім повторіть `npm ci`. |
| Немає доступу до кешу npm (`EACCES`) | Спробуйте локальний кеш: `npm ci --cache .sites-runtime/npm-cache`. |
| Порт 5173 зайнятий | Зупиніть інший сервер або запустіть `npm run dev -- --hostname 127.0.0.1 --port 5174` і відкрийте надруковану адресу. |
| `listen EPERM` у середовищі з обмеженнями | Запустіть команду у звичайному терміналі свого комп’ютера, де дозволено відкривати локальні порти. |
| Не завантажується бенчмарк | Скористайтеся локальним імпортом JSONL у формі створення проєкту. |

## Збереження й перенесення

База SQLite зберігається під **`.wrangler/state/`** і використовується локальним D1 адаптером. Не видаляйте цей каталог, щоб зберегти проєкти. Перезапуск сервера не скидає оцінки чи стан відкриття мітки. Початкове судження після відкриття не редагується; наступні оцінки мають журнал змін. Застаріле збереження з іншої вкладки відхиляється.

Поточні незбережені поля форми мають окрему чернетку в `localStorage` цього браузера. **Чернетка не є завершеною оцінкою й не потрапляє у звіт або резервну копію** — для цього натисніть «Зберегти».

Експорти:

- **Анотації CSV**: UTF-8 із BOM, український текст, початкові й підсумкові рішення, запропоновані значення, примітки та відомості про відбір. Для ще не відкритих прикладів автоматичні значення, індекси джерела й GRAC залишаються порожніми. Потенційні формули екрануються для перегляду в електронних таблицях.
- **Результати JSON**: кількості, частки, охоплення та метод оцінювання; для незавершеного проєкту інтервал і фінальна частка дорівнюють `null`.
- **Резервна копія JSON v1**: повний знімок JSONL, контрольна сума, проєкт, вибірка, збережені судження та журнал. Вона містить усі вихідні мітки; не переглядайте її для прийняття сліпих рішень.
- **Звіт Markdown**: доступний лише після завершення всієї вибірки.

Кнопка «Відновити з резервної копії» створює **новий проєкт**, не перезаписуючи наявний. До запису перевіряються контрольна сума, відтворення вибірки з seed, стани відкриття та послідовність журналу. Незавершений імпорт після аварійної зупинки можна повторити через 10 хвилин: залишки такого імпорту очищуються автоматично.

## Методика

Одиниця відбору — окрема збережена відповідність **речення–значення**. Усі вкладені `examples` розгортаються без дедуплікації чи мовчазного відкидання. Помилка структури зупиняє імпорт. У формі показано всі визначення відповідної леми, **збережені в цій версії бенчмарку**, а не повний вихідний словник. Автоматичне виділення цільового слова не виконується: дані не містять його символьних меж.

SHA-256 ідентифікує точний завантажений UTF-8 вміст. Стабільні непрозорі ID залежать від контрольної суми та позиції запису. Просту випадкову вибірку без повернення реалізовано відтворюваним перемішуванням Fisher–Yates із Mulberry32 та rejection sampling для індексів. Порядок визначень також перемішується відтворювано для кожного прикладу. Алгоритм і його версія фіксуються в проєкті.

Головна оцінка: **підтверджені мітки / вся фіксована вибірка**. Невизначені випадки залишаються у знаменнику, але не прирівнюються до доведених помилок. Фінальні висновки й інтервал недоступні, поки є приклади без підсумкової оцінки.

95% довірчий інтервал отримується інверсією рівнохвостих гіпергеометричних тестів. Для спостереженого `k` серед `n` та сукупності `N` залишаються цілі `K ∈ [k, N−n+k]`, для яких обидві включні хвостові ймовірності не менші за `0.025`; межі діляться на `N`. Обчислення використовує рекурентні логарифмічні маси й нормалізацію, а не нормальне наближення чи квантілі прогнозного розподілу. Планова похибка окремо показує `1.96 × sqrt(0.25/n × (N−n)/(N−1))`.

Гіпергеометрична модель описана в [документації SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.hypergeom.html). Незалежна перевірка меж цілими комбінаторними масами доступна командою `python3 scripts/check-statistics-reference.py`.

Результат є **авторською** валідацією за судженнями одного перевіряльника. Він не оцінює міжанотаторну узгодженість, якість кожного значення окремо або повноту автоматичного добору.

## Розробка та перевірки

```sh
npm run check
npm run build
python3 scripts/check-statistics-reference.py
```

Додаткова перевірка реального зафіксованого JSONL (файл має бути у `data/`):

```sh
npm run test:benchmark
```

Тести використовують справжній SQLite через `node:sqlite` з адаптером D1. Вони перевіряють імпорт, відбір, API запитами без мережі, приховування мітки, помилки дискового запису, конкурентні версії, перезапуск, журнал, експорт/відновлення та статистичне покриття на малих сукупностях. Вони не замінюють перевірку браузерного інтерфейсу.

Після збірки `npm start` запускає зібраний Worker **локально** через Wrangler; це не публікація. Дані залишаються у `.wrangler/state/`. Структура бази ініціалізується автоматично при першому API запиті; схему визначено в `lib/audit/schema.ts`.

### Локальні API

- `GET /api/snapshots`, `POST /api/snapshots` (`raw`), `POST /api/snapshots/download` (`revision`).
- `GET/POST /api/projects`; створення приймає `snapshotId`, `name`, `reviewer`, `seed`, `sampleSize`.
- `GET /api/projects/:id`, `GET /api/projects/:id/items/:exampleId`.
- `POST .../items/:exampleId/reveal` (`choice`, `version`), `POST .../items/:exampleId/assessment` (`assessment`, `version`).
- `POST /api/projects/:id/position` (`position`); `GET .../results`, `GET .../report`.
- `GET /api/projects/:id/export?format=csv|backup|results|markdown`; `POST /api/restore` із резервною копією.

Підсумкові результати: `correct`, `incorrect`, `unresolved`. Початковий вибір — ID значення, `none` або `uncertain`. Усі позиції API починаються з нуля; у формі та CSV нумерація починається з одиниці. Відповіді не кешуються. Зміна параметрів відбору потребує нового проєкту.
